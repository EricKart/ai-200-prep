The big picture

The rule: if a value lets someone get into something (keys, passwords, connection strings), it goes in Key Vault. If it only changes how the app behaves (endpoints, batch sizes, flags), it goes in App Configuration.

SecretAny string up to 25 KB: API key, connection string, password.
VersionEvery save of a secret makes a new version (a GUID). Old ones stay.
Data plane vs control planeReading secrets (data) vs managing the vault resource (control). Different roles.
Managed identityAn Azure-given identity for your app. No password to store.
LabelA variant of the same key, e.g. Production. No label = the "null label".
Feature flagAn on/off switch you flip in Azure, no redeploy.
Sentinel keyOne key you change to tell apps "reload everything now".
Key Vault referenceAn App Configuration value that only points to a Key Vault secret.

--retention-days 7Soft-delete retention: 7 to 90 days (default 90). Set at creation, can't change later. 7 here so a deleted lab vault frees its name sooner.

Being Owner of the subscription lets you manage the vault. It does not let you read or write secrets. That needs a data-plane role.

Explain this command
  • az keyvault show … --query id: the vault's full resource ID (/subscriptions/…/vaults/kv-ai200-…). Roles are always given at a scope, and this ID is the scope.
  • az role assignment create: "give who (--assignee-object-id $ME) which role (--role) where (--scope)".
  • --assignee-principal-type User: tells Azure the ID is a user. That skips a directory lookup that can fail right after sign-in.
  • Scope = this one vault. If you gave the role on the resource group, you'd get secrets in every vault in it. Least privilege = smallest scope.

"""Part 1 - Read secrets from Key Vault with the Python SDK.

What this shows (LP8 Module 1, units 2 and 3):
  1. SecretClient + DefaultAzureCredential (no password or key in code)
  2. get_secret()  -> the value and its metadata (version, content type, tags)
  3. list_properties_of_secrets()  -> names and metadata only, never values
  4. Error handling: a missing secret raises ResourceNotFoundError
"""
import lab_env  # noqa: F401  first import: stops with a clear message if the venv isn't active
from azure.core.exceptions import HttpResponseError, ResourceNotFoundError, ServiceRequestError
from azure.identity import DefaultAzureCredential
from azure.keyvault.secrets import SecretClient

from lab_env import explain_auth_error, need

vault_url = need("KEY_VAULT_URL")

# DefaultAzureCredential tries several sign-in methods in order.
# On your laptop it ends up using your `az login` account (AzureCliCredential).
# On Azure (App Service, Container Apps, AKS...) it would use a managed identity.
credential = DefaultAzureCredential()
client = SecretClient(vault_url=vault_url, credential=credential)

print(f"Vault: {vault_url}\n")

# ---- 1. Get one secret -------------------------------------------------------
print("== 1. get_secret('openai-api-key') ==")
try:
    secret = client.get_secret("openai-api-key")
except HttpResponseError as e:
    explain_auth_error(e)
    raise SystemExit(1)

masked = secret.value[:6] + "..." if secret.value else ""
print(f"  value (masked) : {masked}")        # never print real secrets in real apps

"""Part 3 - Cache secrets so you don't call Key Vault on every request.

What this shows (LP8 Module 1, unit 5):
  1. Without a cache: 20 "requests" = 20 Key Vault calls (slow, and can hit the 429 throttle)
  2. Time-based cache (TTL): 20 requests = 1 Key Vault call
  3. After the TTL passes, the cache fetches a fresh value once
  4. Startup preloading: load every secret once when the app starts
"""
import lab_env  # noqa: F401  first import: stops with a clear message if the venv isn't active
import time

from azure.core.exceptions import HttpResponseError
from azure.identity import DefaultAzureCredential
from azure.keyvault.secrets import SecretClient

from lab_env import explain_auth_error, need

VAULT_URL = need("KEY_VAULT_URL")
credential = DefaultAzureCredential()
client = SecretClient(vault_url=VAULT_URL, credential=credential)


class SecretCache:
    """Same pattern as the Learn module, plus a counter so you can SEE the vault calls."""

    def __init__(self, client, cache_ttl_seconds=900):
        self._client = client
        self._cache = {}
        self._cache_ttl = cache_ttl_seconds
        self.vault_calls = 0

    def get_secret(self, secret_name):
        cached = self._cache.get(secret_name)
        now = time.monotonic()          # clock that ignores system time changes
        if cached and (now - cached["timestamp"]) < self._cache_ttl:
            return cached["value"]      # cache hit, no network call
        secret = self._client.get_secret(secret_name)   # cache miss, call Key Vault
        self.vault_calls += 1
        self._cache[secret_name] = {"value": secret.value, "timestamp": now}
        return secret.value


def handle_requests(get, n=20):
    start = time.perf_counter()
    for _ in range(n):
        get("openai-api-key")
    return (time.perf_counter() - start) * 1000


try:
    client.get_secret("openai-api-key")   # warm-up: sign-in + first connection
except HttpResponseError as e:
    explain_auth_error(e)
    raise SystemExit(1)

# ---- 1. No cache ------------------------------------------------------------
print("== 1. No cache: every request calls Key Vault ==")
ms = handle_requests(lambda name: client.get_secret(name).value)
print(f"  20 requests -> 20 vault calls, {ms:.0f} ms total ({ms / 20:.1f} ms each)")

# ---- 2. TTL cache -----------------------------------------------------------
print("\n== 2. Time-based cache (TTL = 5 seconds for the demo; use 15-60 min in real apps) ==")
cache = SecretCache(client, cache_ttl_seconds=5)
ms = handle_requests(cache.get_secret)
print(f"  20 requests -> {cache.vault_calls} vault call(s), {ms:.0f} ms total ({ms / 20:.3f} ms each)")

# ---- 3. TTL expiry ----------------------------------------------------------
print("\n== 3. Wait 6 seconds so the cached value expires ==")
time.sleep(6)
handle_requests(cache.get_secret)
print(f"  20 more requests -> total vault calls now {cache.vault_calls} (one refresh after the TTL)")

class AppConfig:
    def __init__(self, client, secret_names):
        self._secrets = {name: client.get_secret(name).value for name in secret_names}

    def get(self, secret_name):
        return self._secrets.get(secret_name)


print("\n== 4. Startup preloading ==")

print("\nKey Vault limit to remember: 4,000 GET per vault per 10 seconds -> HTTP 429 if you go over.")

How the code works
  1. handle_requests(get, n=20) pretends to be 20 web requests that each need the API key, and times them.
  2. No cache: lambda name: client.get_secret(name).value. 20 network round trips.
  3. SecretCache: a dictionary {name: {"value", "timestamp"}}. get_secret() checks if the entry is younger than the TTL. If yes, it returns from memory (a "hit"). If not, it calls Key Vault, saves the value with the time, and counts the call (a "miss").
  4. time.monotonic() is a clock that never jumps when the computer's time changes, so TTL maths stays correct.
  5. After time.sleep(6) the 5-second TTL has passed, so exactly one more vault call happens.
  6. AppConfig (preloading) reads all secrets once in __init__. Requests then only read the dictionary.

"""Part 4 - Async client: fetch several secrets at the same time.

What this shows (LP8 Module 1, unit 3, "async client"):
  - azure.keyvault.secrets.aio.SecretClient has the same methods, but you `await` them
  - Both the client and the credential must be closed (async with / await close())
  - asyncio.gather() runs the 3 calls concurrently instead of one after another
"""
import lab_env  # noqa: F401  first import: stops with a clear message if the venv isn't active
import asyncio
import time

from azure.identity.aio import DefaultAzureCredential
from azure.keyvault.secrets.aio import SecretClient

from lab_env import need

NAMES = ["openai-api-key", "cosmosdb-connection-string", "storage-connection-string"]


async def main():
    credential = DefaultAzureCredential()
    client = SecretClient(vault_url=need("KEY_VAULT_URL"), credential=credential)

    async with client:                       # closes the client at the end
        await client.get_secret(NAMES[0])    # warm-up (sign-in)

        start = time.perf_counter()
        for name in NAMES:                   # one after another
            await client.get_secret(name)
        one_by_one = (time.perf_counter() - start) * 1000

        start = time.perf_counter()
        secrets = await asyncio.gather(*(client.get_secret(n) for n in NAMES))   # all at once
        together = (time.perf_counter() - start) * 1000

    await credential.close()                 # the async credential must be closed too

    for s in secrets:
        print(f"  got {s.name:<28} version {s.properties.version[:8]}..")
    print(f"\n  one after another : {one_by_one:.0f} ms")
    print(f"  asyncio.gather    : {together:.0f} ms")
    print("\nDone. Part 4 complete.")


asyncio.run(main())
How the code works
  1. Imports come from azure.identity.aio and azure.keyvault.secrets.aio: same names, async versions.
  2. async with client: closes the client's network connections at the end. The credential is closed separately with await credential.close(). Forgetting either gives "Unclosed client session" warnings.
  3. The for loop awaits each call: the next starts only when the previous one finished.
  4. asyncio.gather(*(...)) starts all three at once and waits for all. Total time ≈ the slowest call, not the sum.
  5. asyncio.run(main()) starts the event loop that runs the async code.

Same methods, imported from .aio, with await. Close both the client and the credential. In FastAPI or aiohttp, create the client once at startup and reuse it.

TTL = int(sys.argv[1]) if len(sys.argv) > 1 else 20   # optional: python 05_kv_rotation_watch.py 600
kv = SecretClient(vault_url=need("KEY_VAULT_URL"), credential=DefaultAzureCredential())

cache = {"value": None, "version": None, "at": 0.0}


def log(msg):
    print(f"[{datetime.now():%H:%M:%S}] {msg}", flush=True)


def load_secret(reason):
    s = kv.get_secret(SECRET)
    if s.properties.version != cache["version"]:
        log(f"  Key Vault -> version {s.properties.version[:8]}.. ({reason})  <-- NEW VALUE")
    cache.update(value=s.value, version=s.properties.version, at=time.monotonic())


def get_conn():
    if cache["value"] is None or time.monotonic() - cache["at"] >= TTL:
        load_secret("cache TTL expired" if cache["value"] else "first load")
    return cache["value"]


def call_storage(conn):
    # A real, authenticated call. It fails with 403 if the key in `conn` was regenerated.
    # Short retries so the demo reacts in seconds (the SDK default waits 15 s, then longer).
    svc = QueueServiceClient.from_connection_string(
        conn, retry_policy=ExponentialRetry(initial_backoff=1, increment_base=2, retry_total=2),
        connection_timeout=10, read_timeout=10)
    return [q.name for q in svc.list_queues()]


def call_downstream(max_retries=1):
    conn = get_conn()
    for attempt in range(max_retries + 1):
        try:
            return call_storage(conn)
        except (ClientAuthenticationError, HttpResponseError) as e:
            if getattr(e, "status_code", None) not in (401, 403) or attempt == max_retries:
                raise
            log("  Storage rejected the key (403). The credential was probably rotated. Re-reading Key Vault...")
            load_secret("refetch after auth failure")
            conn = cache["value"]


try:
    get_conn()
except HttpResponseError as e:
    explain_auth_error(e)
    raise SystemExit(1)

log(f"Watching. Calling Azure Storage every 3 s. Cache TTL = {TTL} s. Press Ctrl+C to stop.")
ok = failed = 0
try:
    while True:
        try:
            queues = call_downstream()
            ok += 1
            log(f"OK   storage call #{ok:<3} using version {cache['version'][:8]}..  queues={queues}")
        except Exception as e:  # noqa: BLE001 - show any failure to the student
            failed += 1
            log(f"FAIL {type(e).__name__}: {str(e).splitlines()[0][:110]}")
        time.sleep(3)
except KeyboardInterrupt:
    print(f"\nStopped. Successful calls: {ok}, failed calls: {failed}.")
    print("Zero failed calls during the rotation = zero downtime. Part 5 complete.")
How the code works
  1. cache holds the connection string, its version, and when it was loaded.
  2. get_conn(): if nothing is cached, or the cache is older than TTL, it calls load_secret(), which reads the latest version from Key Vault. It prints <-- NEW VALUE when the version changed.
  3. call_storage(conn) does a real, signed request: it lists the queues in the account. With a dead key, Azure answers 403. The short ExponentialRetry keeps the demo fast. The SDK default waits much longer.
  4. call_downstream() is the retry-on-auth-failure pattern. On a 401/403 it assumes "the key was rotated", re-reads Key Vault (ignoring the cache) and tries once more. Any other error, or a second failure, is raised.
  5. The while True loop counts OK and FAIL calls. Ctrl+C raises KeyboardInterrupt, and the script prints the totals.

"""Part 6 - Event-driven cache invalidation with Event Grid.

Key Vault -> Event Grid -> Storage queue "kv-events" -> this script.

When a new version of ANY secret is created, Key Vault emits a
Microsoft.KeyVault.SecretNewVersionCreated event. Event Grid drops it in the queue.
This script reads the queue, removes that secret from its cache, and the next read
fetches the fresh value. A long TTL (1 hour) stays as a safety net in case an event is lost.

Leave this running. In terminal 2, run `az keyvault secret set ...` and watch.
Stop with Ctrl+C.
"""
import lab_env  # noqa: F401  first import: stops with a clear message if the venv isn't active
import base64
import json
import time
from datetime import datetime

from azure.identity import DefaultAzureCredential
from azure.keyvault.secrets import SecretClient
from azure.storage.queue import QueueClient

from lab_env import need

kv = SecretClient(vault_url=need("KEY_VAULT_URL"), credential=DefaultAzureCredential())

# The app gets its OWN storage credential from Key Vault too (no keys in code).
queue = QueueClient.from_connection_string(kv.get_secret("storage-connection-string").value, "kv-events")

cache = {}           # name -> (value, version, loaded_at)
TTL = 3600           # fallback refresh, 1 hour


def log(msg):
    print(f"[{datetime.now():%H:%M:%S}] {msg}", flush=True)


def get(name):
    hit = cache.get(name)
    if hit and time.monotonic() - hit[2] < TTL:
        return hit
    s = kv.get_secret(name)
    cache[name] = (s.value, s.properties.version, time.monotonic())
    log(f"  cache MISS -> fetched '{name}' from Key Vault, version {s.properties.version[:8]}..")
    return cache[name]


def decode(msg):
    raw = msg.content
    try:
        return json.loads(raw)
    except json.JSONDecodeError:
        return json.loads(base64.b64decode(raw))   # Event Grid writes Base64 text to queues


get("openai-api-key")
log("Listening for Key Vault events on queue 'kv-events'. Ctrl+C to stop.")
log("Now run in terminal 2:  az keyvault secret set --vault-name <vault> --name openai-api-key --value sk-demo-NEW")
try:
    while True:
        for msg in queue.receive_messages(messages_per_page=16, visibility_timeout=30):
            event = decode(msg)
            etype = event.get("eventType", "?")
            name = event.get("data", {}).get("ObjectName", "?")
            version = event.get("data", {}).get("Version", "")
            log(f"EVENT {etype}  secret={name}  version={version[:8]}..")
            if etype.endswith("SecretNewVersionCreated") and name in cache:
                cache.pop(name)
                log(f"  invalidated '{name}' in the cache")
            queue.delete_message(msg)
        value, version, _ = get("openai-api-key")       # what a request would read right now
        log(f"request reads openai-api-key -> version {version[:8]}..  value starts '{value[:10]}'")
        time.sleep(5)
except KeyboardInterrupt:
    print("\nStopped. Part 6 complete.")
How the code works
  1. The script reads its own storage connection string from Key Vault (no keys in code), then opens the kv-events queue with QueueClient.
  2. get(name) is a normal TTL cache, but with a long TTL (1 hour) as a safety net.
  3. Every 5 seconds, queue.receive_messages() takes up to 16 messages. visibility_timeout=30 hides them from other readers while this one works on them.
  4. decode(): Event Grid writes the event as Base64 text into the queue, so the code decodes it, then parses the JSON. eventType says what happened. data.ObjectName and data.Version say which secret and version.
  5. On SecretNewVersionCreated it removes that secret from the cache (cache.pop). The next read is a "MISS" and fetches the new value.
  6. queue.delete_message(msg) marks the message as handled. Without it, the message would come back after 30 seconds.
Defense in depthEvent Grid gives near-real-time freshness. The long TTL (1 hour) is the safety net if an event is ever lost. Event Grid can deliver to a webhook, an Azure Function, or a Service Bus / Storage queue. We used a Storage queue because it needs no public endpoint.

How the code works
  1. Attempt 1 calls load() without keyvault_credential. The provider finds a Key Vault reference it can't resolve and raises ValueError. It refuses to hand you a half-loaded config.

  • No version in the URI (recommended) = always the latest version, so rotation needs no config change. Add /<version> only to pin one.

"""Part 10 - Dynamic refresh with a sentinel key (no restart).

import time
from datetime import datetime

from azure.appconfiguration.provider import SettingSelector, WatchKey, load
from azure.identity import DefaultAzureCredential
from featuremanagement import FeatureManager

from lab_env import need

credential = DefaultAzureCredential()
config = load(
    endpoint=need("AZURE_APPCONFIG_ENDPOINT"),
    credential=credential,
    keyvault_credential=credential,
    selects=[SettingSelector(key_filter="DocPipeline:*", label_filter="\0")],
    refresh_on=[WatchKey("Sentinel")],
    refresh_interval=10,
    feature_flag_enabled=True,
    feature_flag_refresh_enabled=True,
    secret_refresh_interval=60,
)

def snapshot():
    return (config["DocPipeline:Pipeline:BatchSize"], config["DocPipeline:Pipeline:RetryCount"],
            feature_manager.is_enabled("UseNewEmbeddingsModel"), config["DocPipeline:OpenAI:ApiKey"][:12])


print("Watching. BatchSize / RetryCount refresh via Sentinel; flags refresh by themselves; secret every 60 s.")
last = None
try:
    while True:
        try:
            config.refresh()                  # cheap: returns at once if 10 s haven't passed
        except Exception as e:  # noqa: BLE001 - a network blip must not kill the app
            print(f"  (refresh failed: {type(e).__name__}; keeping the last known values)")
        now = snapshot()
        tag = "  <-- CHANGED" if last and now != last else ""
        print(f"[{datetime.now():%H:%M:%S}] BatchSize={now[0]:<4} RetryCount={now[1]:<3} "
              f"UseNewEmbeddingsModel={str(now[2]):<5} ApiKey={now[3]}...{tag}", flush=True)

How the code works
  1. load(...) sets up everything once: which keys (selects), what to watch (refresh_on=[WatchKey("Sentinel")]), how often to check (refresh_interval=10), flags with their own refresh, and secrets re-read every 60 s.
  2. Nothing refreshes by itself. The loop calls config.refresh() every 5 seconds. If less than 10 s passed since the last check, it returns immediately without a network call.
  3. When the sentinel changed, the provider reloads all selected keys. The same config object now has the new values.
  4. refresh() is wrapped in try/except: a network blip keeps the last known values instead of crashing the app.
  5. snapshot() reads the four values. If they differ from the last loop, the line gets <-- CHANGED.

The test: could this value alone let someone access a resource? Then Key Vault. Does it only change behaviour? Then App Configuration. Sort these:

Anti-patterns (exam favourites)

  • Secrets directly in App Configuration: no per-object audit, HSM, expiry or rotation.

  • Values hard-coded in code or files: you lose updates without redeploying.
