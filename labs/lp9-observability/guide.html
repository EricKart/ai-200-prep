The big picture

Three pillars: metrics tell you that something changed, traces tell you where, logs tell you why.

TraceOne request's whole journey. All its spans share a trace ID (= operation_Id).
SpanOne timed operation: name, start/end, parent, attributes, status.
Context propagationPassing the trace ID to the next service in the W3C traceparent header.
Distroazure-monitor-opentelemetry: OTel SDK + Azure exporter + auto-instrumentation in one package.
ExporterSends telemetry to a backend. OTel is vendor-neutral, so you can swap backends without re-instrumenting.
Cloud role nameservice.namespace.service.name. One node per role on the Application Map.
SamplingKeep only some traces to save cost. itemCount says how many each row stands for.
KQLKusto Query Language: table | operator | operator, top to bottom.

The traceparent header

traceparent: 00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01
             ^^ version  ^^ trace ID (32 hex)          ^^ parent span ID (16 hex)  ^^ flags (01 = sampled)

📄 telemetry.py 48 lines
"""One function every service calls FIRST, before importing Flask.

configure_azure_monitor() (the Azure Monitor OpenTelemetry Distro) sets up:
  - traces  -> requests / dependencies tables
  - logs    -> traces table (Python's logging module is hooked in automatically)
  - metrics -> customMetrics table
and auto-instruments Flask (incoming requests) and the requests library (outgoing calls).

Where does it get its settings? From environment variables, so the code has no secrets:
  APPLICATIONINSIGHTS_CONNECTION_STRING  where to send telemetry
  OTEL_SERVICE_NAME                      e.g. "api-gateway"
  OTEL_RESOURCE_ATTRIBUTES               e.g. "service.namespace=rag-pipeline,service.instance.id=gw-1"
  OTEL_TRACES_SAMPLER / _ARG             sampling (run_demo.py sets these)
Cloud role name on the Application Map = service.namespace + "." + service.name

The same thing in code (the other option shown in Learn) would be:
  from opentelemetry.sdk.resources import Resource
  configure_azure_monitor(resource=Resource.create({"service.name": "api-gateway",
                                                    "service.namespace": "rag-pipeline"}))
"""
import logging
import os
import sys

from azure.monitor.opentelemetry import configure_azure_monitor


def setup_telemetry():
    if not os.environ.get("APPLICATIONINSIGHTS_CONNECTION_STRING"):
        print("[!] APPLICATIONINSIGHTS_CONNECTION_STRING is not set in this terminal. Paste the guide's 'New terminal' block.")
        sys.exit(1)
    configure_azure_monitor(
        logger_name="rag",                 # only loggers named "rag..." are sent (keeps Flask noise out)
        enable_live_metrics=True,          # on by default; written here so you can see it
    )
    logger = logging.getLogger("rag")
    logger.setLevel(logging.INFO)
    return logger


def flush_telemetry():
    """Push everything that's still buffered to Application Insights (used before shutdown)."""
    from opentelemetry import metrics, trace
    from opentelemetry._logs import get_logger_provider

    for provider in (trace.get_tracer_provider(), metrics.get_meter_provider(), get_logger_provider()):
        if hasattr(provider, "force_flush"):
            provider.force_flush()
  • configure_azure_monitor(), called once at startup, sets up the tracer, meter and logger providers, all exporting to Application Insights. It must run before Flask is imported, so Flask gets instrumented.
  • Python's logging is wired in automatically → the traces table. logger_name="rag" sends only our loggers, not Flask's access log.
📄 services/gateway.py 43 lines
"""Service 1 of 3: the API gateway (cloud role "rag-pipeline.api-gateway").

GET /ask?q=...&scenario=...  -> calls the orchestrator.
No custom spans here at all: Flask and requests are auto-instrumented, so you still get
a SERVER span (requests table) and a CLIENT span (dependencies table), and the
`traceparent` header is added to the outgoing call for you (context propagation).
"""
import os
import sys

sys.path.insert(0, os.path.dirname(os.path.dirname(os.path.abspath(__file__))))
from telemetry import flush_telemetry, setup_telemetry  # noqa: E402

log = setup_telemetry()           # MUST run before Flask is imported

import requests  # noqa: E402
from flask import Flask, jsonify, request  # noqa: E402
from opentelemetry import trace  # noqa: E402

app = Flask(__name__)
ORCHESTRATOR = os.environ.get("ORCHESTRATOR_URL", "http://127.0.0.1:5002")


@app.get("/ask")
def ask():
    q = request.args.get("q", "How do I reset my password?")
    scenario = request.args.get("scenario", "normal")
    trace_id = format(trace.get_current_span().get_span_context().trace_id, "032x")
    log.info("Gateway received question (scenario=%s)", scenario)
    r = requests.post(f"{ORCHESTRATOR}/process", json={"q": q, "scenario": scenario}, timeout=30)
    body = r.json()
    body["trace_id"] = trace_id   # = operation_Id in Application Insights
    return jsonify(body), r.status_code


@app.post("/flush")
def flush():
    flush_telemetry()
    return "flushed"


if __name__ == "__main__":
    app.run(host="127.0.0.1", port=int(os.environ.get("PORT", "5001")))

The gateway has no custom spans at all. Auto-instrumentation still gives it a request (incoming) and a dependency (outgoing). The requests library adds the traceparent header for you.

📄 services/orchestrator.py 116 lines
"""Service 2 of 3: the RAG orchestrator (cloud role "rag-pipeline.llm-orchestrator").

This is where the CUSTOM instrumentation lives (LP9 Module 1, unit 4):
  tracer = trace.get_tracer(...)                       one tracer per component
  with tracer.start_as_current_span("Name") as span:   a timed operation (ends automatically)
  span.set_attribute("embedding.model", ...)           -> customDimensions in Application Insights
  kind=SpanKind.CLIENT                                 -> dependencies table, type "InProc"/HTTP
  span.record_exception(ex) + span.set_status(ERROR)   -> exceptions table + failed span
Nested `with` blocks become parent -> child spans automatically.

Request flow for POST /process:
  [SERVER span from Flask] POST /process
     ├─ GenerateEmbedding     (INTERNAL)
     ├─ SearchVectorIndex     (INTERNAL)  slow "cold start" after 20 s of no searches
     ├─ AssemblePrompt        (INTERNAL)  fails if the prompt is bigger than the context window
     └─ CallLlm               (CLIENT)
           └─ POST /v1/chat   (auto: requests library -> llm-service)
"""
import os
import random
import sys
import time

sys.path.insert(0, os.path.dirname(os.path.dirname(os.path.abspath(__file__))))
from telemetry import flush_telemetry, setup_telemetry  # noqa: E402

log = setup_telemetry()

import requests  # noqa: E402
from flask import Flask, jsonify, request  # noqa: E402
from opentelemetry import metrics, trace  # noqa: E402
from opentelemetry.trace import SpanKind, Status, StatusCode  # noqa: E402

app = Flask(__name__)
tracer = trace.get_tracer("llm-orchestrator")
meter = metrics.get_meter("llm-orchestrator")
docs_counter = meter.create_counter("documents_retrieved", description="Documents returned by vector search")

LLM_URL = os.environ.get("LLM_URL", "http://127.0.0.1:5003")
CONTEXT_WINDOW = 128_000
last_search = 0.0


class ContextWindowExceededError(Exception):
    pass


@app.post("/process")
def process():
    global last_search
    data = request.get_json()
    query, scenario = data["q"], data.get("scenario", "normal")
    # The header that carried the trace across the service boundary (W3C TraceContext):
    log.info("traceparent received: %s", request.headers.get("traceparent"))

    # ---- 1. Embedding ---------------------------------------------------------
    with tracer.start_as_current_span("GenerateEmbedding") as span:
        tokens = len(query.split()) * 4
        span.set_attribute("embedding.model", "text-embedding-3-small")
        span.set_attribute("embedding.token_count", tokens)
        time.sleep(random.uniform(0.08, 0.2))
        span.set_attribute("embedding.dimensions", 1536)

    # ---- 2. Vector search (cold start after idle) --------------------------------
    with tracer.start_as_current_span("SearchVectorIndex") as span:
        cold = time.monotonic() - last_search > 20
        span.set_attribute("search.index_name", "product-docs")
        span.set_attribute("search.top_k", 5)
        span.set_attribute("search.cold_start", cold)
        time.sleep(3.5 if cold else random.uniform(0.05, 0.2))
        results = random.randint(3, 5)
        span.set_attribute("search.result_count", results)
        span.set_attribute("search.similarity_threshold", 0.78)
        last_search = time.monotonic()
        docs_counter.add(results, {"index": "product-docs"})

    # ---- 3. Prompt assembly (context window overflow) ----------------------------
    with tracer.start_as_current_span("AssemblePrompt") as span:
        prompt_tokens = 150_000 if scenario == "overflow" else random.randint(900, 2500)
        span.set_attribute("llm.prompt_tokens", prompt_tokens)
        try:
            if prompt_tokens > CONTEXT_WINDOW:
                raise ContextWindowExceededError(f"Prompt has {prompt_tokens} tokens; limit is {CONTEXT_WINDOW}")
            span.set_status(Status(StatusCode.OK))
        except ContextWindowExceededError as ex:
            span.record_exception(ex)
            span.set_status(Status(StatusCode.ERROR, "Prompt exceeds context window"))
            log.error("Context window overflow: %s", ex)
            return jsonify(error=str(ex)), 500

    # ---- 4. LLM call (CLIENT span wrapping a real HTTP call) ---------------------
    with tracer.start_as_current_span("CallLlm", kind=SpanKind.CLIENT) as span:
        span.set_attribute("llm.provider", "azure-openai")
        span.set_attribute("llm.model", "gpt-4o-mini")
        payload = {"q": query, "scenario": scenario, "request_id": random.random()}
        r = requests.post(f"{LLM_URL}/v1/chat", json=payload, timeout=30)
        if r.status_code == 429:
            span.set_attribute("llm.retry_after_429", True)
            log.warning("LLM returned 429, retrying after Retry-After")
            time.sleep(float(r.headers.get("Retry-After", "1")))
            r = requests.post(f"{LLM_URL}/v1/chat", json=payload, timeout=30)
        answer = r.json()
        span.set_attribute("llm.response_tokens", answer["usage"]["completion_tokens"])

    log.info("Answered query with %d documents", results)
    return jsonify(answer=answer["answer"], documents=results, scenario=scenario)


@app.post("/flush")
def flush():
    flush_telemetry()
    return "flushed"


if __name__ == "__main__":
    app.run(host="127.0.0.1", port=int(os.environ.get("PORT", "5002")))

"""Service 3 of 3: a fake LLM API (cloud role "rag-pipeline.llm-service").

It behaves like a real model endpoint on a bad day, depending on the `scenario` sent:
  normal      -> answers in 0.3-0.7 s
  slow-llm    -> answers in about 5.5 s        (latency bottleneck)
  rate-limit  -> first call gets HTTP 429      (token rate limiting), the retry succeeds
No custom code for telemetry: Flask auto-instrumentation records every call.
"""
import os
import random
import sys
import time

sys.path.insert(0, os.path.dirname(os.path.dirname(os.path.abspath(__file__))))
from telemetry import flush_telemetry, setup_telemetry  # noqa: E402

log = setup_telemetry()

from flask import Flask, jsonify, request  # noqa: E402

app = Flask(__name__)
seen_rate_limit = set()


@app.post("/v1/chat")
def chat():
    data = request.get_json()
    scenario = data.get("scenario", "normal")
    if scenario == "rate-limit" and data["request_id"] not in seen_rate_limit:
        seen_rate_limit.add(data["request_id"])
        log.warning("Token rate limit hit, returning 429")
        return jsonify(error="Too Many Requests: token rate limit exceeded"), 429, {"Retry-After": "1"}
    time.sleep(5.5 if scenario == "slow-llm" else random.uniform(0.3, 0.7))
    return jsonify(answer="Open Settings > Security > Reset password.",
                   usage={"completion_tokens": random.randint(40, 120)})


@app.post("/flush")
def flush():
    flush_telemetry()
    return "flushed"


if __name__ == "__main__":
    app.run(host="127.0.0.1", port=int(os.environ.get("PORT", "5003")))

def start_services(sampling):
    if not os.environ.get("APPLICATIONINSIGHTS_CONNECTION_STRING"):
        sys.exit("[!] APPLICATIONINSIGHTS_CONNECTION_STRING is not set in this terminal. Paste the guide's 'New terminal' block.")
    (HERE / "logs").mkdir(exist_ok=True)
    procs = []
    for file, name, port in SERVICES:
        env = dict(os.environ)
        env.update(
            PORT=str(port),
            OTEL_SERVICE_NAME=name,
            OTEL_RESOURCE_ATTRIBUTES=f"service.namespace=rag-pipeline,service.instance.id={name}-1",
            OTEL_TRACES_SAMPLER="microsoft.fixed_percentage",
            OTEL_TRACES_SAMPLER_ARG=str(sampling),
            PYTHONUNBUFFERED="1",
            # Keep the data clean: don't record the /flush helper or the SDK's own calls...
            OTEL_PYTHON_EXCLUDED_URLS="flush,settings.sdk.monitor.azure.com,169.254.169.254",
            # ...and skip the Azure VM / App Service detectors (they probe 169.254.169.254,
            # which times out on a laptop and shows up as fake ConnectTimeout exceptions).
            OTEL_EXPERIMENTAL_RESOURCE_DETECTORS="otel",
        )
        out = open(HERE / "logs" / f"{name}.log", "w")
        procs.append(subprocess.Popen([sys.executable, str(HERE / "services" / file)], env=env,
                                      stdout=out, stderr=subprocess.STDOUT))
    for _, name, port in SERVICES:                       # wait until each one answers
        for _ in range(60):
            try:
                requests.post(f"http://127.0.0.1:{port}/flush", timeout=2)
                break
            except requests.ConnectionError:
                time.sleep(0.5)
        else:
            stop(procs)
            sys.exit(f"[!] {name} did not start. Look at logs/{name}.log")
    print(f"3 services running (sampling = {sampling}).")
    return procs


def stop(procs):
    for _, _, port in SERVICES:
        try:
            requests.post(f"http://127.0.0.1:{port}/flush", timeout=15)   # send buffered telemetry
        except requests.RequestException:
            pass
    for p in procs:
        p.terminate()
    for p in procs:
        p.wait(timeout=10)


def call(scenario, q="How do I reset my password?"):
    start = time.perf_counter()
    try:
        r = requests.get(f"{GATEWAY}/ask", params={"q": q, "scenario": scenario}, timeout=40)
        status, trace_id = r.status_code, r.json().get("trace_id", "")
    except requests.RequestException as e:
        status, trace_id = f"ERR {type(e).__name__}", ""
    ms = (time.perf_counter() - start) * 1000
    print(f"  {scenario:<11} -> HTTP {status}  {ms:6.0f} ms  operation_Id={trace_id}")


def traffic(failures):
    print("\nRound 1 (first search is a COLD START):")
    for s in ["normal"] * 8 + ["slow-llm", "normal", "rate-limit", "normal", "overflow", "normal", "slow-llm"]:
        call(s)
    print("\nIdle 25 s so the vector index goes cold again...")
    time.sleep(25)
    print("Round 2:")
    for s in ["normal"] * 10 + ["rate-limit", "slow-llm", "overflow", "rate-limit", "normal", "overflow"] + ["normal"] * 8:
        call(s)
    if failures:
        print(f"\nFailure burst: {failures} requests that overflow the context window:")
        for _ in range(failures):
            call("overflow")


def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("--sampling", type=float, default=1.0, help="0.0-1.0, share of traces kept")
    ap.add_argument("--failures", type=int, default=0, help="extra failing requests to send")
    ap.add_argument("--serve", action="store_true", help="keep services running until Ctrl+C")
    args = ap.parse_args()

    procs = start_services(args.sampling)
    try:
        if args.serve:
            print(f"Open {GATEWAY}/ask  or  {GATEWAY}/ask?scenario=slow-llm  (also: rate-limit, overflow)")
            print("Press Ctrl+C to stop.")
            while True:
                time.sleep(1)
        traffic(args.failures)
    except KeyboardInterrupt:
        pass
    finally:
        print("\nFlushing telemetry and stopping services...")
        stop(procs)
    print("Done. Data appears in Application Insights in about 2-5 minutes.")


if __name__ == "__main__":
    main()
How run_demo.py works
  1. import lab_env first: it stops with instructions if the venv isn't active.
  2. start_services() starts the 3 services as separate processes (subprocess.Popen), like 3 microservices. Each gets its own environment: PORT, OTEL_SERVICE_NAME (api-gateway / llm-orchestrator / llm-service), OTEL_RESOURCE_ATTRIBUTES (namespace rag-pipeline), and the sampler settings. Each one's output goes to logs/<name>.log.
  3. It waits until each service answers on its /flush URL, or tells you which log to read if one didn't start.
  4. traffic() sends about 40 requests to the gateway with different scenario values. It waits 25 s in the middle so the next search is a cold start again. --failures N adds N overflow requests at the end.
  5. stop() calls /flush on every service, so buffered telemetry is sent before the processes end. Then it stops them. Without the flush, the last few seconds of data would be lost.
  6. The two OTEL_… "keep the data clean" lines stop the Distro recording its own helper calls and probing for an Azure VM (which times out on a laptop).

Export pipeline facts

  • Direct export (default): the app sends straight to the ingestion endpoint. The alternative, the OpenTelemetry Collector, is a separate process for central sampling, transformation and multi-backend routing (more to run).
  • Offline storage: if the network drops, the exporter caches to disk and retries for up to 48 hours. Default folder: <temp>/Microsoft-AzureMonitor-<hash>/opentelemetry-python-<ikey>. Change it with storage_directory=, or turn it off with disable_offline_storage=True (not recommended).

2. Log search alert: failure spike (Severity 1)

az monitor scheduled-query create --name alert-failure-spike --resource-group $RG \
  --scopes $AI_ID \
  --condition "count 'FailedServices' > 0" \
  --condition-query "FailedServices=requests | where success == false | summarize failedCount = count() by cloud_RoleName | where failedCount > 10" \
  --window-size 5m --evaluation-frequency 5m --severity 1 \
  --action-groups $AG_ID \
  --description "A service had more than 10 failed requests in 5 minutes" \

  --scopes $AI_ID `
  --condition "count 'FailedServices' > 0" `
  --condition-query "FailedServices=requests | where success == false | summarize failedCount = count() by cloud_RoleName | where failedCount > 10" `

  --action-groups $AG_ID `
  --description "A service had more than 10 failed requests in 5 minutes" `
  --query "{name:name, enabled:enabled, severity:severity}" -o table
Explain this command
  • --condition-query FailedServices="…": the KQL (from Learn) returns one row per service with more than 10 failures.
  • --condition "count 'FailedServices' > 0": measure = table rows, threshold > 0. Fire if any service is returned.
  • --window-size 5m: aggregation granularity (the time the query looks at). --evaluation-frequency 5m: how often it runs (1 min to 24 h).
  • Optional --violations: require several bad evaluations before firing, which cuts noise from one-off spikes.

3. Log search alert: p95 latency (Severity 2)

az monitor scheduled-query create --name alert-p95-latency --resource-group $RG \
  --scopes $AI_ID \
  --condition "count 'SlowServices' > 0" \
  --condition-query "SlowServices=requests | summarize p95Duration = percentile(duration, 95) by cloud_RoleName | where p95Duration > 3000" \
  --window-size 15m --evaluation-frequency 5m --severity 2 \
  --action-groups $AG_ID \
  --description "p95 response time above 3 seconds" \
  --query "{name:name, enabled:enabled, severity:severity}" -o table
az monitor scheduled-query create --name alert-p95-latency --resource-group $RG `
  --scopes $AI_ID `
  --condition "count 'SlowServices' > 0" `
  --condition-query "SlowServices=requests | summarize p95Duration = percentile(duration, 95) by cloud_RoleName | where p95Duration > 3000" `
  --window-size 15m --evaluation-frequency 5m --severity 2 `
  --action-groups $AG_ID `
  --description "p95 response time above 3 seconds" `
  --query "{name:name, enabled:enabled, severity:severity}" -o table
Explain this command
  • Same shape as the failure alert. The query computes percentile(duration, 95) per service and keeps services above 3000 ms. The rule fires when any row comes back.
  • --window-size 15m: percentiles need enough data, so it looks at 15 minutes. --evaluation-frequency 5m: it still checks every 5 minutes.
  • --severity 2 (Warning) vs 1 (Error) for failures: slow is bad, broken is worse.

p95 instead of average: an average can look fine while the slowest 5% of users suffer.

6. Smart detection (no thresholds)

Application Insights → Investigate → Smart detection. Machine learning learns your normal baseline and warns about failure anomalies (abnormal rise in the failure rate, with a cluster analysis of affected users, exceptions and dependencies) and performance anomalies (slower responses or dependencies, exception volume, including slow drift that never crosses a fixed number). It needs days of history, so it won't trigger in this lab. Use both: manual alerts for known SLAs ("p95 < 3 s"), smart detection for surprises.

Mac: every az command prints a long Traceback ending in os.getcwd() … PermissionError: [Errno 1] Operation not permitted

Check yourself (exam style)

Score: not started

1. Your custom span uses SpanKind.INTERNAL. Which Application Insights table holds it?

INTERNAL, CLIENT and PRODUCER → dependencies. SERVER and CONSUMER → requests. The traces table is logs.

2. You call span.set_attribute("search.top_k", 5). Where do you query it?

Span attributes → customDimensions, e.g. customDimensions["search.top_k"].

3. Four services all appear as ONE node on the Application Map. What's missing?

The cloud role name comes from service.namespace + service.name.

4. The connection string is set in code AND in APPLICATIONINSIGHTS_CONNECTION_STRING. Which is used?

For the connection string, code wins. (For sampling, environment variables win, so learn both.)

5. Sampling is on. Which expression gives the real number of exceptions?

Each stored row represents itemCount events. Step 10 showed 11 rows = 44 requests.

6. Which value in the traceparent header equals operation_Id?

32 hex = trace ID = operation_Id. 16 hex = the parent span ID.

7. You need to alert when p95 latency per service exceeds 3 s, grouped by cloud_RoleName. Which alert type?

Percentiles per dimension need KQL, so a log search alert.

8. Operators want to pick a service from a dropdown and have every chart filter to it. Which tool?

Parameters and drill-down are what workbooks do.

9. Where does a log line from logging.getLogger("rag").info(...) end up?

Log records → the traces table (confusing name, exam favourite).

10. Which statement about sampling is true?

Metrics are never sampled. The default is RateLimitedSampler. Environment variables win over code for sampling.
